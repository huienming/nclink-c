## 1. 范围

规定 NC-Link 中**设备对象、组件对象、数据对象**的类型数据项。适用于数控机床、工业机器人、
自动搬运车、清洗设备、检测设备、自动化生产线、自动料库等数控装备（监控传感器/执行器的
工业附属设备参照使用）。

## 5. 与本仓库实现的对照

### 5.1 已经一致的

- 设备节点的 `device.type` = `MACHINE`（`conf/fanuc.json`）与表 1 一致。
- 模型路径的**首段**用 `MACHINE`（本次把 `/CNC/...` 改成 `/MACHINE/...`：`CNC` 不是
  标准里的类型名，设备对象只有表 1 那七个取值）。
- **模型里每个 `type` 都是本册的名字**（2026-09 收口，2026-09 又扩了一轮）：
  `STATUS`/`WARNING`/`PART_COUNT`/`PROGRAM`/`PROGRAM_NUMBER`/`LINE_NUMBER`/`WORK_MODE`/
  `POSITION`/`ANGLE`/`SPEED`/`PATH_LEFT_LENGTH`/`TORQUE`/`CURRENT`/`TEMPERATURE`/
  `TOOL`/`TOOLPARAM`/`VARIABLE`/`PARAMETER`/`COORDINATE`/`TYPE`/`MODEL`/`VERSION`/
  `MANUFACTURER` —— 一个不例外（完整对照见 5.2）。
- **"读得到"和"字典里有"是两回事**：字典里有、FANUC 侧还没核准的，点位照样声明、
  照样绑函数，函数回 `NCL_ERR_UNAVAILABLE`（模型里有它、问它有明确答复、轮询与审计都
  不碰）—— 见 5.2 的 🟡 与 5.3。

### 5.1.1 数据对象的两种归置：`dataItems` 与 `configs`

第 3 部分把数据对象放在两个数组里，本册的数据项按"变不变"分：

| 归置 | 是什么 | 本册里的 type |
|---|---|---|
| `dataItems` | **可以采集的数据**：物理量与从设备感知的实时量；采样通道只能引用它们 | 表 4 全部（`POSITION`/`SPEED`/`CURRENT`…）+ 表 6 的 `STATUS`、`WARNING` + 表 7 的 `PART_COUNT`、`PROGRAM`、`PROGRAM_NUMBER`、`SUBPROGRAM`、`LINE_NUMBER`、`TOOL_NUMBER`、`FEED_OVERRIDE`、`SPINDLE_OVERRIDE`、`PATH_LEFT_LENGTH`、`CONSOLE`、`SITE`、`WORK_MODE`、`PART` |
| `configs` | **配置信息**：参数、坐标系、刀具表这类不常变的数据，可查询/可修改；**表 1 注 b：配置中的数据对象不得作为采样数据源** | 表 6 的 `CREATE_TIME`、`CREATOR`、`MANUFACTURER`、`MODEL`、`NAME`、`NUMBER`、`PARAMETER`、`VERSION` + 表 7 的 `COORDINATE`、`FILE`、`SHELF_UNIT`、`TOOL`、`TOOLPARAM`、`TYPE`、`VARIABLE` |

实现上**写声明时就得说清是哪一类**：`NCL_DATAITEM_*` 一族进 `dataItems`，
`NCL_CONFIG_*` 一族进 `configs`（`ncl_tool_model()` 据此把点放进设备/组件的两个数组）。
`NCL_CONFIG_*` 没有 `_SAMPLED` 形式，手写表把两者同时置位会被校验直接拒掉
（"配置型数据不得作为采样数据源"）。
**可写必然可读**：没有只写的数据对象 —— 审计要记下写之前的旧值，读不回来的写也没法
确认，所以手写表声明成"只写"同样会被校验拒掉。设备真只收命令的（口令、复位脉冲、
清零）在实现里是 `NCL_METHOD`，不是数据对象。
**操作按位声明**：点位声明它答标准第 5 部分的哪些操作 —— 表 11 的 `get_value` /
`get_length` / `get_keys` / `get_attributes`、表 13 的 `set_value` / `add` / `delete`
与方法调用。集合（list / dict / JSON 对象）类型的数据对象（`FILE`、`TOOL`、`TOOLPARAM`、
`VARIABLE` 这些）就是靠 `NCL_DATAITEM_OPS` / `NCL_CONFIG_OPS` 把集合操作写全的；
没声明的操作由宿主回表 2 的 `Unsupported Operation`。
**`dataType` 也跟本册走**：本册"类型"列是集合的那几项，声明式工具生成的模型就写出来 ——
dict / JSON 对象 → `"dataType": "HASH"`（`WARNING`、`FILE`、`PARAMETER`、`PART`、
`TOOLPARAM`），list → `"LIST"`（`COORDINATE`、`SHELF_UNIT`、`TOOL`、`VARIABLE`）；标量
（string / number）不写这一项。

按现场核对过的两处：`PARAMETER` 就是 `HASH`（参数本身是字典）；`COORDINATE` 是 `LIST`
（一张表，跟刀具表一样）。

> ⚠️ 现场有的点表用 `TOOL_PARAM` 这个名字（28 册的交付清单、29 册的现场模型、Brother /
> KEDE GNC62 的点表）—— 那是**现场自定**的名字，本册里没有。实现层只认册子上的名字：
> **刀具列表是 `TOOL`**（list）、**刀具参数是 `TOOLPARAM`**（JSON 对象）。现场那份模型
> 要么改成这两个名字，要么就当厂商自定 type（模型里不写 `dataType`）。

上面那张 type 清单是**核对用的**：声明里的类型名来自本册，归置来自宏，两边对不上时
（比如把 `PARAMETER` 写成 `NCL_DATAITEM_*`）宿主打一条告警提醒复核。本册查不到的厂商
自定 `type` 由声明决定归置、默认按 `dataItems`。采样通道对象本身也是 `configs` 的一员
（第 3 部分 5.3 就是这么放的）。

#### F. 默认采样通道的口径（现场要求，2026-09 定）

只放**设备状态、加工计件、程序名称、报警**四条（表里 ✅ 的那几个）：`STATUS`、
`PART_COUNT`、`CONTROLLER/PROGRAM`、`WARNING`。位置、速度、倍率一律按需读。这不是本
部分规定的事 —— 要改就把声明行的 `NCL_DATAITEM` ↔ `NCL_DATAITEM_SAMPLED` 换一下
（CPU 采样通道在模型 `configs` 里，按 `type: SAMPLE_CHANNEL` 找，别认下标：设备级的
config 点位（`MANUFACTURER`/`MODEL`/`VERSION`）排在它前面）。

模型树：`device(MACHINE) → component(CONTROLLER / AXIS@X …) → dataItem`。组件层由声明里的
**中段路径**生成（`ncl_tool_model()` 会建组件节点，`/MACHINE/AXIS@X/POSITION@REAL` 就落在
`AXIS@X` 组件下），设备节点自己答在 `/MACHINE` 上。

**每个节点的 `name` 就是本册那张表里的中文含义**（表 4/表 6/表 7 的"含义"列，组件用表 2）：
`STATUS` → 运行状态、`PART_COUNT` → 加工件数、`PROGRAM` → 主程序名、`WARNING` → 报警信息、
`POSITION` → 位置、`SPEED` → 速度、`AXIS` → 轴。数据项带 `number` 时缀在后面
（`POSITION@REAL` → 位置（实际）、`POSITION@CMD` → 位置（目标）、`POWER@1` → 功率（1）），
组件则把轴号放在前面（`AXIS@X` → X 轴）。本册查不到的 `type`（厂商自定的）照原名。
**名字只给人看**：路径由 `type`（与 `number`）在树里拼出来，改名不会动路径。

### 5.3 还没定的（在 [31 册](31-待真机抓包清单.md) 里跟踪）

上一轮把两件事定了：**`cnc_actf` 是实际进给速度、`cnc_acts` 是实际主轴转速**（官方手册
原文 + 线上实测），**坐标类调用的请求码是 item `0x26`**（01 册 §3.3）。现在剩下的是
"应答怎么切"：

- **坐标（`0x26`）· 已定**：`cnc_rdposition` 的应答是**每轴一个 `POSELM`（12 字节）**——
  `int32 data` + `dec` + `unit` + `disp` + 轴名，值 = `data / 10^dec`（NCGuide 实测
  `dec = 3`、轴名 'X'，01 册 §10.1）。同族的 `cnc_srvdelay`（d = 9）是**每轴 8 字节**、
  值在记录第 0 个 int32——两个量相减就是**指令位置**（现场口径：跟踪误差 = 实际 − 指令）。
- **报警 `WARNING`（`0x23`）**：请求码已核（d = 报警类型、e = 条数），应答按
  `ODBALMMSG2` 数组切（`alm_no`/`type`/`axis`/`msg_len`/`alm_msg[64]`）—— 真机核一次
  就能填。**值的形状**：表 9 的 `WARNING` 是一个 JSON 对象（`number`/`text`/`key_value`），
  多条报警时是"一条一个对象"还是数组（第 3 部分允许任意 JSON value）也要一起定。
- **负载（`0x56`+`0x89` 伺服、`0x40`+`0x8a` 主轴）**：请求码已核，`LOADELM`
  数组（`data`/`dec`/`unit`/`name`）的偏移待核。
- **`cnc_rdblkcount`（`0x35`）/ `cnc_rdopmode`（`0x57`）**：码已核，取值不在载荷 0 处。
- **程序上传（`0x15`/`0x18`）**：请求码已核（含定长 516 字节的 start 体、数据帧 dir=4），
  差**应答里程序文本的切法** —— 官方库在内部函数里解，反汇编到那一层没再往下。
- **刀补/参数/宏变量（`0x08`/`0x0e`/`0x15`）**：帧早就抓到了，字段布局一直没核
  （需要真机或 NCGuide 回真实载荷）。

> 最省事的收口：FANUC 自己的 **NCGuide**（官方模拟器）带 FOCAS2 服务 —— 不用真机，
> 起一个模拟机床就能把这些 🟡 的应答抓全（01 册 §3.3 的工具链直接可用）。
- **厂商私有量（FANUC 的 ODBST 位域）不进模型**：本册是一份**封闭**的名字表 —— 它列了
  设备类型（表 1）、组件类型（表 2/表 3）和三类数据项（表 4/6/7），没有"厂商自定义名字"
  的位置；第 3 部分的模型对象也只认 `type` 能在本册查到的数据对象。所以 `STATINFO` 里那些
  位（手动、自动、编辑、移动、急停、主轴、操作者…）**不作为数据项出现在模型里**：
  - 能用本册名字表达的，就派生成本册的名字 —— `/MACHINE/STATUS` 就是 RUN 与 EMERGENCY
    两位推出来的 `running`/`free`/`holding`（表 6 + 表 8）；
  - 想要"手动/自动"，正解是表 7 的 `WORK_MODE`（取值 `manual`/`auto`，表 8），由 ODBST 的
    手动方式位（块 0 偏移 0）与自动方式位（块 2）推出来；现在**没声明**，现场要就加一条。
  - 纯粹只有 FANUC 才有的量，通过适配器自己的调试方法 `focas/ITEMS` 看（那是驱动的项表，
    不是模型），不进模型、也不上报。
