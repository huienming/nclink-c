# 32 · 标准第 4 部分：数据项定义

> **来源**：标准原文（10 页 PDF，文字版可提取）——`数控装备工业互联通讯协议 第4部分：
> 数据项定义.pdf`（T/CMTBA XXXX.4—××××，**送审讨论稿**）。
> **证据级**：🔵 标准（逐表记录）。
> **本册用途**：模型里能出现哪些**数据项名字**、每个名字的**类型/单位/适用范围**，以及
> 与本仓库适配器实现的**对照**。写点位声明（`adapters/plugins/*.c`）时以本册为准。

NC-Link 全套 7 部分：1 通用技术条件 · 2 联网参考模型 · **3 数控装备模型定义** ·
**4 数据项定义** · 5 终端及接口定义 · 6 安全性 · 7 评价规范。第 4 部分规范性引用第 1、3 部分：
`dict` / JSON 对象 / `list` 的**形状**由第 3 部分规定，本部分只定义**数据项本身**。

## 1. 范围

规定 NC-Link 中**设备对象、组件对象、数据对象**的类型数据项。适用于数控机床、工业机器人、
自动搬运车、清洗设备、检测设备、自动化生产线、自动料库等数控装备（监控传感器/执行器的
工业附属设备参照使用）。

## 4. 数据对象的数据项

数据对象的数据项分三类：**物理量数据项**（表 4）、**通用数据项**（表 6）、**专用数据项**（表 7）。

### 4.1 物理量数据项（表 4，全部是 `number`）

| Type | 默认单位 | 含义 |
|---|---|---|
| `ACCELERATION` | 毫米每秒平方 | 加速度 |
| `ANGLE` | 弧度 | 角位置 |
| `ANGULAR_ACCELERATION` | 角度数每秒平方 | 角加速度 |
| `ANGULAR_VELOCITY` | 角度数每秒 | 角速度 |
| `CONCENTRATION` | 百分数 | 浓度 |
| `CONDUCTIVITY` | 西门子每米 | 导电力 |
| `CURRENT` | 安培 | 电流 |
| `DISPLACEMENT` | 毫米 | 位移 |
| `ENERGY` | 瓦特小时 | 功耗 |
| `FLOW` | 升每秒 | 流体瞬时流量 |
| `FREQUENCY` | 赫兹 | 频率 |
| `LENGTH` | 毫米 | 长度 |
| `MASS` | 千克 | 质量 |
| `POSITION` | 毫米 | 位置 |
| `POWER` | 瓦特 | 功率 |
| `POWER_FACTOR` | 百分比 | 功率因数 |

| ℃ | ℉ | 温度 |

### 4.3 通用数据项（表 6）

| Type | 类型 | 单位 | 含义 |
|---|---|---|---|
| `CREATE_TIME` | string | 无 | 创建时间 |
| `CREATOR` | string | 无 | 创建者 |
| `MANUFACTURER` | string | 无 | 厂商 |
| `MODEL` | string | 无 | 型号 |
| `NAME` | string | 无 | 名称 |
| `NUMBER` | number | 无 | 编号 |
| `PARAMETER` | dict | 无 | 参数 |
| **`STATUS`** | **string** | 无 | **数控装备、组件运行状态**（取值见表 8） |
| `VERSION` | string | 无 | 版本 |
| `WARNING` | JSON 对象 | 无 | 报警信息（形状见表 9） |

> **只有 `STATUS` 这一个运行状态项**：它没有 `STATUS@xxx` 这种子项，取值是
> `running` / `free` / `holding`（表 8）。协议私有的位域（某型号的编辑/移动/急停位…
> 属于厂商私有，不能占用 `STATUS` 这个名字）。

### 4.5 组合定义（表 8）

数据对象的 `type` 取特定值时，`value` 的取值集合：

| 数据对象 type | value 取值 | 类型 | 含义 |
|---|---|---|---|
| `TYPE` | `rotary` | string | 旋转轴 |
| `TYPE` | `linear` | string | 线性轴 |
| `STATUS` | `running` | string 或整数 `0` | 运行 |
| `STATUS` | `free` | string 或整数 `1` | 空闲 |
| `STATUS` | `holding` | string 或整数 `2` | 紧急保持（产线上等上料即处于此态） |
| `WORK_MODE` | `manual` | string | 手动 |
| `WORK_MODE` | `auto` | string | 自动 |

| 数据对象 type | JSON 元素 | 类型 | 含义 |
|---|---|---|---|
| `COORDINATE` | `x,y,z` | number | 线性轴坐标系 |

| | `u,v,w` | number | 摆动轴坐标系 |
| | `x1,y1,z1 … xn,yn,zn` | number | 多通道线性 |

## 5. 与本仓库实现的对照

### 5.1 已经一致的

- 设备节点的 `device.type` = `MACHINE`（`conf/fanuc.json`）与表 1 一致。
- 模型路径的**首段**用 `MACHINE`（本次把 `/CNC/...` 改成 `/MACHINE/...`：`CNC` 不是
  标准里的类型名，设备对象只有表 1 那七个取值）。
- `POSITION`、`SPEED` 是表 4 的物理量数据项 ✓（FANUC 适配器读的 `ACTF`/`ACTS` 正是
  位置与速度）。
- **模型里每个 `type` 都是本册的名字**（2026-09 收口）：`STATUS`、`PART_COUNT`、`WARNING`、
  `PROGRAM`、`POSITION`、`SPEED` 一个不例外；凡是本册没有名字的量，就不进模型（见 5.3）。

### 5.2 FANUC 适配器现在的口径（2026-09 已按本册改过一轮）

| 点位 | 依据 | FOCAS 侧 | 默认采样 |
|---|---|---|---|
| `/MACHINE/STATUS`（string：`running`/`free`/`holding`） | 表 6 + 表 8 | 一次读 `STATINFO` 前十个 int16，用 RUN 与 EMERGENCY 两位推导三态 | ✔ |
| `/MACHINE/PART_COUNT`（string） | 表 7 | `RDCOUNT`（int32 读回来转成字符串） | ✔ |
| `/MACHINE/CONTROLLER/PROGRAM`（string） | 表 7 + 表 2（`PROGRAM` 属于 `CONTROLLER` 组件） | `EXEPRGNAME2` | ✔ |
| `/MACHINE/WARNING`（报警：JSON `number`/`text`） | 表 6 + 表 9 | **未抓到帧**（`cnc_rdalmmsg2`，见 5.3）→ 声明为 `NCL_POINT_PENDING_SAMPLED`：占着通道，取值是 `null` | ✔（值为 null） |
| `/MACHINE/AXIS@X|Y|Z|A|C/POSITION@REAL`（number 位置） | 表 4 `POSITION` + 表 3 轴名 | `ACTF@4k`（01 册 §3.2：全部轴绝对位置 float 数组） | ✘ 按需读 |
| `/MACHINE/AXIS@k/POSITION@CMD`（目标位置） | 同上 | **未抓到帧**（见 5.3）→ `NCL_POINT_PENDING_NAMED`，问它返回明确错误 | ✘ 按需读 |
| `/MACHINE/AXIS@k/SPEED`（速度） | 表 4 `SPEED`（默认毫米每分钟） | `ACTS@4k`（**量纲待核**：01 册 §3.2 把 `cnc_acts` 也写成"全部轴绝对位置"，与"速度"这个名字冲突） | ✘ 按需读 |

**默认采样通道的口径**（现场要求，2026-09 定）：只放**设备状态、加工计件、程序名称、报警**
四条 —— 表里 ✔ 的那些。位置、速度一律 `NCL_POINT_ARG`（按需读）。这与本部分不冲突：
哪一项该进通道是现场口径，不是数据项定义规定的事；要改就把声明行的
`NCL_POINT_ARG` ↔ `NCL_POINT_SAMPLED_ARG` 换一下。

模型树：`device(MACHINE) → component(CONTROLLER / AXIS@X …) → dataItem`。组件层由声明里的
**中段路径**生成（`ncl_tool_model()` 会建组件节点，`/MACHINE/AXIS@X/POSITION@REAL` 就落在
`AXIS@X` 组件下），设备节点自己答在 `/MACHINE` 上。

### 5.3 还没定的（在 [31 册](31-待真机抓包清单.md) 里跟踪）

- **目标位置 CMD 的帧**：01 册 §2.3 的 Cb 码表里没有坐标类调用（`cnc_absolute` /
  `cnc_rdposition` 都没进到协议层），所以声明成"待抓包"（`NCL_POINT_PENDING_NAMED`）：
  模型里有、问它返回 `NCL_ERR_NOT_SUPPORTED` 与原因、轮询直接跳过，不给假值。
- **`ACTS` 到底是位置还是速度**：01 册 §3.2 的索引把 `cnc_acts`/`cnc_actf` 都写成
  "全部轴绝对位置（short/float）"，而适配器一直把 `ACTS` 当速度用；Fwlib 手册里
  `cnc_actf` 是"实际进给速度"、`cnc_acts` 是"实际主轴转速"。两种读法结论不同，
  要一次真机（或抓到 `cnc_rdaxisdata` 的帧，01 册 §2.3 第 215 行说它本地就失败了）才能定。
- **报警 `WARNING`**：已声明 `/MACHINE/WARNING`（`NCL_POINT_PENDING_SAMPLED`：按现场口径占着
  默认采样通道，抓包补上之前那一列是 `null`），但 FOCAS 侧取报警号/文本要用
  `cnc_rdalmmsg2` 一类调用，**该帧同样没抓到**（01 册 §2.3 第 215 行）→ 读数返回明确错误。
  **值的形状待定**：表 9 说 `WARNING` 是一个 JSON 对象（`number`/`text`/`key_value`），而一台
  机器可能同时有多条报警 —— 是"一个对象一条"还是"一个数组"（第 3 部分允许 `value` 是任意
  JSON value，所以两种都合法），要等一次真机抓包。
- **厂商私有量（FANUC 的 ODBST 位域）不进模型**：本册是一份**封闭**的名字表 —— 它列了
  设备类型（表 1）、组件类型（表 2/表 3）和三类数据项（表 4/6/7），没有"厂商自定义名字"
  的位置；第 3 部分的模型对象也只认 `type` 能在本册查到的数据对象。所以 `STATINFO` 里那些
  位（手动、自动、编辑、移动、急停、主轴、操作者…）**不作为数据项出现在模型里**：
  - 能用本册名字表达的，就派生成本册的名字 —— `/MACHINE/STATUS` 就是 RUN 与 EMERGENCY
    两位推出来的 `running`/`free`/`holding`（表 6 + 表 8）；
  - 想要"手动/自动"，正解是表 7 的 `WORK_MODE`（取值 `manual`/`auto`，表 8），由 ODBST 的
    手动方式位（块 0 偏移 0）与自动方式位（块 2）推出来；现在**没声明**，现场要就加一条。
  - 纯粹只有 FANUC 才有的量，通过适配器自己的调试方法 `focas/ITEMS` 看（那是驱动的项表，
    不是模型），不进模型、也不上报。
