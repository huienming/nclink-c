# 00 · 通用实现约定

> 所有协议分册共享的工程约定。编码时先读本文，再读具体协议册。

---

## 1. 抽象接口（建议签名）

```
interface IDeviceSession:
    Open(transport, host, port, opts) -> Result<sessionId>
    Close(sessionId) -> Result
    IsConnected(sessionId) -> bool
    ReadBatch(sessionId, list<Address>) -> Result<list<Value>>
    WriteBatch(sessionId, list<(Address, Value)>) -> Result
    ReadRaw(sessionId, byte[] request) -> Result<byte[]>     // 逃生舱：直发原始报文
    WriteRaw(sessionId, byte[] request) -> Result<byte[]>

struct Address:                    // 统一地址模型（参考商业库 DeviceAddressDataBase）
    area:   string                 // 数据区：M/D/X/Y/DB/CIO...
    offset: int64                  // 偏移或编号
    bit:    int                    // 位号（-1 = 非位寻址）
    length: int                    // 读取长度（元素个数）
    dtype:  enum{BIT,BYTE,INT16,INT32,FLOAT32,FLOAT64,STRING}

struct Result<T>:                  // 统一响应信封（参考参考实现T2Res / 商业库 OperateResult）
    code:    int                   // 0 = 成功
    success: bool
    value:   T
    message: string                // 人类可读
    raw:     byte[]                // 原始报文（调试/审计）
```

## 2. 三类错误分级（必须分开）

| 层级 | 例 | 处理 |
|---|---|---|
| **传输层** | TCP 超时、连接断开、发包失败 | 自动重连（指数退避）；不重试写操作，除非幂等 |
| **协议层** | 错误码返回（如 `ME_DEV_TIMEOUT=20`、`LSV2_WRONG_BBC=6`、`EZ_ERR_NOT_OPEN`） | 按码表映射；部分可重试（超时类） |
| **业务层** | 数据无效（机床报警中、坐标为 0、超出量程） | 上报，不改协议状态 |

统一编码建议：`0x0000_0000` 成功 · `0x1xxx_xxxx` 传输 · `0x2xxx_xxxx` 协议 · `0x3xxx_xxxx` 业务。

## 3. 连接与重连

```
连接参数默认值（可按协议覆盖）：
  连接超时  3s        // TCP connect
  读超时    按协议（机床类 5s；PLC 类 1-3s；LSV2 15s）
  写超时    同上
  心跳      TCP keepalive(60s) 或协议级（如 MC 的 0x0619 环回测试）
  重连      指数退避 1s→2s→4s→8s→30s(上限)，连续失败 5 次转告警
  半开检测  业务调用超时即判定；不要只依赖 TCP keepalive
```

**要点**：
- 机床类协议（MELDAS/LSV2/RemoteCNC）**多为单会话独占**，重连前必须先发 Close，否则设备侧会话残留导致新连接被拒。
- MC/S7/FINS 支持多连接，但很多 PLC 限制了并发数（常见 4-8），连接池要设上限。
- 写操作重连后必须重新校验状态（不要盲重放）。

## 4. 字节序与编码（**最常见的坑**）

| 协议 | 字节序 | 说明 |
|---|---|---|
| 三菱 MC | 二进制帧小端；ASCII 帧大端 | 同一协议两种编码，别混 |
| 三菱 MELDAS(GIOP) | **小端**（帧头 flags=0x01） | double 有 8 字节和 10 字节两种 |
| S7comm | **大端** | 所有字/双字 |
| Modbus | **大端**（寄存器内） | 但寄存器顺序可配（字交换） |
| FINS | 大端 | — |
| FOCAS | 小端（x86 DLL） | — |
| LSV2 | 长度字段**大端**（`!L`），字符串为命令名 | — |
| HSES | 小端 | — |

**字符串**：中文场景注意 GBK/UTF-8/Shift-JIS（三菱面板多为 Shift-JIS，海德汉用 ISO-8859-1）。
**浮点**：S7 的 REAL 是 IEEE754 大端；三菱 MELDAS 有 10 字节扩展精度格式（见 05 册）。

## 5. 批量读优化

```
1) 地址排序 + 连续性合并：相邻地址合并为一次请求（阈值：间隔 ≤ 4 字节时合并更优）
2) 单请求上限：S7 (PDU/2-4 字节头) ≈ 200-900 字节；MC ≤ 960 字；Modbus ≤ 125 寄存器；FINS ≤ 999 字
3) 超限则分片，分片失败只重试该片
4) 高低频分离：高频点位（坐标/速度，50-200ms）单独连接或单独请求队列
```

## 6. 日志与审计（设备接入必备）

必须记录（结构化，可回放）：
- 会话生命周期（open/close/reconnect/原因）
- **每次请求的原始报文 hex + 耗时 + 响应码**（可开关，生产环境按需采样）
- 协议层错误码直方图（定位是线缆还是协议问题）
- 写操作全量审计（改了哪个地址、旧值、新值、操作者）

## 7. 安全边界

| 项 | 约定 |
|---|---|
| 只读 vs 可写 | 写能力必须显式开启（配置 `allowWrite=set<area>`），默认只读 |
| 参数写入 | 机床参数（如三菱 #1925-1929、海德汉 MP）改动需二次确认 + 记录 |
| 程序上下载 | 校验文件名白名单，防止误删（`DEL`/`C_FD` 类命令需人工确认） |
| 凭据 | 设备口令（如三菱 `MPARA`、LSV2 登录名）不得硬编码；走配置/密钥管理 |
| 网络 | 设备网段与管理网隔离；协议端口按需开放，禁全端口扫描入生产 |

## 8. 测试策略

| 层次 | 手段 |
|---|---|
| 单元 | 报文构造/解析纯函数测试（用真实抓包样本做 golden case） |
| 集成 | 虚拟靶机：商业库 47 个虚拟服务器；或自建 Mock（回放抓包） |
| 回归 | 每协议一套 golden 抓包（连接+典型读写），报文级 diff |
| 现场 | 先用示例读点位验证，再开放写；每类机床留一台「金标准」机器 |
