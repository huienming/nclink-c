# 25 · 宝元 LNC（台湾）实现规格书

> **证据**：🟡 公开实证（跨平台采集方案文章 + 现场 SOP）· 🔵 三路通讯方式已确认
> **定位**：**台湾第一大数控品牌**，在中小机床/车床/雕铣领域保有量大，**采集免授权**

---

## 1. 速查

| 项 | 值 |
|---|---|
| 型号 | 旧：**T300 / M300 / T508 / T5800A / D 系列**；新：**M6800 控制器的 5800 系列** |
| 主协议 | **UDP 端口 1700**（跨平台通用，**小端数据解析**） |
| 备选协议 | **Modbus TCP / RTU**（需设备 PLC 程序升级）· **官方 SDK**（新版全兼容） |
| 设置入口 | 软键盘【**DGNOS**】→【网络】设 IP |
| 官方工具 | **ReCON**（官网技术支持页下载） |
| 授权 | **免授权** |
| 参考实现侧 | 无（该品牌是本次新增覆盖） |

---

## 2. 三条通讯路线（新版三种方式）

| 路线 | 兼容性 | 前置条件 | 推荐度 |
|---|---|---|---|
| **① 跨平台 UDP 通讯** | **所有版本兼容** | 无（机床侧开网络即可） | ★★★ 首选 |
| **② 官方 SDK 通讯** | 新版全兼容 | 需厂家 SDK | ★★ 数据最全 |
| **③ Modbus TCP/RTU** | 需设备侧支持 | **需设备 PLC 程序升级** | ★ 有门槛 |

> 实测建议：**先试 UDP（1700）**，采不到的项再考虑 SDK；Modbus 路线需要机床侧改 PLC 程序，落地成本最高。

---

## 3. UDP 协议（端口 1700）

| 项 | 值 |
|---|---|
| 端口 | **1700**（UDP） |
| 字节序 | **小端**（报文按小端解析） |
| 报文 | 固定/半固定长度二进制帧（具体字段布局见 LNC 采集手册） |
| 采集方式 | 上位机主动请求 → 机床响应（或机床周期上报，视固件） |

**典型实现步骤**：
```
① 设好机床 IP（DGNOS → 网络）
② 上位机 UDP socket 绑定，向 1700 发请求帧
③ 收响应帧，按小端解析各字段
④ 字段映射到业务模型（程序号/坐标/状态/报警…）
⑤ 循环采集（建议 500-1000ms）
```

**⚠️ 报文细节缺口**：UDP 帧的**字段偏移表**未公开获取（在 LNC 采集手册/付费资料内）。交付版建议：现场抓包 + 状态变更比对法反推（见 §6）。

---

## 4. Modbus 路线（备选）

```
① 设备侧 PLC 程序升级（厂家/代理配合）
② 上位机走标准 Modbus TCP（502）或 RTU
③ 地址映射按 LNC 提供的 Modbus 地址表
④ 典型能力：EMG 信号、状态、坐标（有 C# 采集实例参考）
```

---

## 5. 实现坑

1. **UDP 无连接**：需自己做请求超时 + 重传 + 序号校验（丢包表现为数据跳变）。
2. **小端解析**（与 Modbus 的大端相反）—— 解析代码不要复用 Modbus 的字节序工具。
3. **版本差异**：旧 T/M 系列与新 5800 系列（M6800）报文可能不同 → 实现时按版本分支或做自动探测。
4. **Modbus 需改 PLC 程序**：客户侧配合成本高，很多现场不接受。
5. **IP 设置要权限**：进入网络设置可能需切换"机床厂权限"。
6. **官方 SDK 更稳**：若数据项多且要求稳定，优先拿 SDK。

---

## 6. 报文反推方法（用于补齐字段表）

```
① tcpdump/Wireshark 抓 UDP 1700 双向流量
② 逐字段比对：改变机床状态（启动/停止/换程序/改倍率）时观察哪些字节变化
③ 高频变化字段 = 坐标/速度；低频 = 状态；事件驱动 = 报警
④ 用"已知量"校验：面板上显示的坐标值 × 缩放系数 应等于报文中的某段（小端整数）
⑤ 交叉验证：同一语义在 Modbus 路线的寄存器值
```
