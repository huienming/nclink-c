# 15 · 通用 Modbus 实现规格书

> **证据**：🔵 标准公开协议 · 参考实现车用多驱动底层 · `pymodbus 3.15.0` 参考
> **定位**：覆盖面最广的工业协议（仪表/PLC/变频器/传感器/称重/电力）

---

## 1. 速查

| 变体 | 端口/接口 | 帧 | 字节序 |
|---|---|---|---|
| **Modbus TCP** | TCP 502 | MBAP(7) + PDU | 大端 |
| **Modbus RTU** | RS-485 / RS-232 | 地址(1) + PDU + CRC16(2) | 大端 |
| **Modbus ASCII** | 串口 | `:` + 地址 + PDU + LRC + CRLF | 十六进制文本 |
| **RTU over TCP** | TCP 任意 | RTU 帧（含 CRC）走 TCP | 大端 |
| **ASCII over TCP** | TCP 任意 | ASCII 帧走 TCP | — |
| **Modbus UDP** | UDP 502 | 同 TCP | 大端 |

**串口参数（RTU 默认）**：9600-8-N-1（也有 19200/38400/115200），CRC16 多项式 **0xA001**（反向）

---

## 2. 帧格式

### 2.1 Modbus TCP（MBAP + PDU）

```
MBAP 头（7 字节）：
  0  2  事务 ID（自增，响应回显）
  2  2  协议 ID（0x0000）
  4  2  后续长度（= 单元 ID 1 + PDU 长度）
  6  1  单元 ID（网关场景用；直连常填 0x01 或 0xFF）
PDU：
  7  1  功能码
  8  N  数据
```

### 2.2 Modbus RTU

```
  0     1  从站地址（1-247；0=广播）
  1     1  功能码
  2     N  数据
  N+2   2  CRC16（低字节在前！多项式 0xA001）
帧间隔：≥3.5 字符时间（115200 时约 1.75ms）—— **超时判定靠静默间隙**
```

## 3. 功能码表

| 码 | 名称 | 访问 | 数量上限 |
|---|---|---|---|
| `0x01` | Read Coils | 线圈（可读写位） | 2000 |
| `0x02` | Read Discrete Inputs | 离散输入（只读位） | 2000 |
| `0x03` | **Read Holding Registers** | 保持寄存器（可读写） | **125** |
| `0x04` | **Read Input Registers** | 输入寄存器（只读） | **125** |
| `0x05` | Write Single Coil | 写单个线圈（0xFF00=ON, 0x0000=OFF） | 1 |
| `0x06` | Write Single Register | 写单个寄存器 | 1 |
| `0x07` | Read Exception Status | 读异常状态 | — |
| `0x08` | Diagnostics | 诊断（含环回测试 0x0000） | — |
| `0x0B` | Get Comm Event Counter | 通信事件计数 | — |
| `0x0C` | Get Comm Event Log | 通信事件日志 | — |
| `0x0F` | Write Multiple Coils | 写多个线圈 | 1968 |
| `0x10` | **Write Multiple Registers** | 写多个寄存器 | **123** |
| `0x11` | Report Server ID | 从站 ID | — |
| `0x16` | Mask Write Register | 掩码写寄存器 | 1 |
| `0x17` | Read/Write Multiple Registers | 读写组合 | 读125/写121 |
| `0x18` | Read FIFO Queue | 读 FIFO | 31 |
| `0x14`/`0x15` | File Record 读写 | 文件记录 | — |

### 3.1 读保持寄存器（0x03）

```
请求：地址(2) + 数量(2)          例：00 00 00 0A = 从 0 起读 10 个
响应：字节数(1) + 数据(N)        例：14 <20 字节>
```

### 3.2 写多个寄存器（0x10）

```
请求：起始地址(2) + 数量(2) + 字节数(1) + 数据(N)
响应：起始地址(2) + 数量(2)     （回显）
```

## 4. 数据映射与类型

| 概念 | 说明 |
|---|---|
| 线圈 (Coil) | 0x 区，可读写位（00001-09999 传统编号） |
| 离散输入 | 1x 区，只读位（10001-19999） |
| 输入寄存器 | 3x 区，只读字（30001-39999） |
| 保持寄存器 | 4x 区，可读写字（40001-49999） |
| **0-based vs 1-based** | 协议里是 0-based；设备手册常用 1-based（40001 = 地址 0）—— **最常见的 off-by-one 来源** |

**数据类型（多寄存器组合）**：
| 类型 | 寄存器数 | 字节序变体 |
|---|---|---|
| INT16 / UINT16 | 1 | 大端 |
| INT32 / UINT32 / FLOAT32 | 2 | **ABCD / CDAB / BADC / DCBA**（字交换 + 字节交换）——必须可配置 |
| INT64 / FLOAT64 | 4 | 同上，8 种排列 |

---

## 5. 实现要点

```
读优化：
  1) 合并相邻请求（间隔 ≤ 8 个寄存器时合并通常更优）
  2) 单次 ≤ 125 寄存器（0x03/0x04）
  3) 高频点位与低频点位分连接/分队列
  4) 失败重试：RTU 建议 2 次；TCP 建议 1 次（避免设备侧状态漂移）

RTU 特有：
  - 3.5 字符静默间隔（t3.5）判定帧边界；实现里用"读超时"近似
  - CRC16 低字节在前（与 CAN/其它协议相反）
  - 广播（地址 0）无响应，不要等
  - 半双工：485 收发切换需要延时（部分转换器需要）
```

---

## 6. 异常响应

```
响应：功能码 | 0x80（最高位置 1） + 异常码(1)
```

| 异常码 | 含义 | 处理 |
|---|---|---|
| `0x01` | 非法功能码 | 设备不支持，换功能码或走自定义 |
| `0x02` | **非法数据地址** | 地址越界/区不存在 |
| `0x03` | **非法数据值** | 数量超限或值非法 |
| `0x04` | 从站设备故障 | 设备自身异常 |
| `0x05` | 确认（处理中） | 稍后重试 |
| `0x06` | 从站忙 | 稍后重试 |
| `0x08` | 存储奇偶校验错 | 重试 |
| `0x0A` | 网关路径不可用 | 网关配置问题 |
| `0x0B` | 网关目标无响应 | 下游设备离线 |

---

## 7. 实现坑

1. **地址 0/1 基准**（见 §4）—— 配置项必须显式声明。
2. **寄存器字节序**：32 位数据在 2 个寄存器里的排列有 4 种；**必须每设备可配**（常见 CDAB 是"字交换"）。
3. **RTU CRC 低字节在前**，与直觉相反。
4. **数量上限随功能码不同**（0x03 ≤125，0x10 ≤123，0x01 ≤2000）。
5. **RTU 帧边界依赖静默间隔**，用 USB-485 转换器时驱动缓冲会破坏这个假设 —— 优先用"按长度读"或换 TCP 网关。
6. **广播写无响应**，超时逻辑要跳过。
7. **同一 485 总线上多从站**时，请求必须串行（不能并发），否则总线冲突。
