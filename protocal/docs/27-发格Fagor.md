## 2. 主方案：宏程序 TCP 主动上报（推荐）

### 2.1 原理

```
机床侧：写一段 CNC 宏程序（O 程序），用官方宏函数 TCPOPEN 连到采集网关，
        然后周期性把系统变量值写入 socket（主动上报）
采集侧：只需监听一个 TCP 端口（如 8899），接收并解析数据
```

**优势**：不轮询、不需 SDK、不需授权、不需硬件加装、**跨平台**（采集端任何语言/系统）。

### 2.2 宏程序骨架（示例形态）

```
; O9999  FAGOR8055/A  TCP 数据主动上报程序
; 采集网关 IP:192.168.1.100  监听端口:8899
; 官方原生宏函数，无授权、无硬件加装需求
#100 = TCPOPEN(...)          ; 打开到网关的 TCP 连接
; 循环：读系统变量 → 写入 socket
;   #10221 / #10201 / #104XX / #10301 / #10501 （见 §3）
```

> ⚠️ 括号内参数与写 socket 的宏函数名未完整公开 —— 补齐方式见 §5。

## 3. 标准系统变量表（官方系统变量手册）

| 变量 | 含义 |
|---|---|
| **`#10221`** | **状态** |
| **`#10201`** | **主轴转速** |
| **`#104XX`** | **坐标**（10401=X, 10402=Y, 10403=Z … 按轴递增） |
| **`#10301`** | 进给类 |
| **`#10501`** | 工具/补偿类 |

> 这 5 组是官方系统变量手册中的**固定标准采集变量**，也是行业采集方案的标准点位。

## 5. 实现坑与补齐路径

1. **P24 参数改 IP 后必须重启**才生效。
2. **宏程序方案依赖机床侧写程序权限** —— 需机床厂/客户授权写 O 程序；部分客户会限制。
3. **TCP 连接需保活**：网络抖动后宏程序侧要能重连（或用循环重建连接）。
4. **坐标系变量按轴递增**（#10401 起），多轴机床注意偏移。
5. **补齐宏函数全表**：抓取机床自带的【宏函数手册】或用 `TCPOPEN` 试跑，把开/关/写/读 socket 的宏函数逐个确认 → 可升级为 🟢 级方案。
