## 2. 连接建立

```
① TCP connect(192.168.x.x, 683)
② 无握手 —— 直接发 GIOP 请求报文
③ 会话保持：请求 ID 自增（4 字节），响应按 ID 匹配
④ 关闭：直接 TCP close 或发 mochaCancelModal
```

**注意**：机床侧仅在 `#1925=1` 时才监听；`#1929` 改端口后需重启网络。

## 3. 帧格式（字节级）

### 3.1 请求（80 字节定长）

```
偏移  长度  内容                典型值            说明
0     4     47 49 4f 50         "GIOP"            CORBA 魔数
4     2     01 00               1.0               版本
6     1     01                  —                 标志位（0x01 = 小端）
7     1     00                  —                 消息类型（0=Request, 1=Reply）
8     4     44 00 00 00         68                正文长度 = 总长 - 12（LE）
12    4     00 00 00 00         —                 保留
16    4     请求ID              任意               **LE，响应按此匹配**
20    4     01 ff ff ff         1                 response_expected=1 + 保留 3 字节
24    4     04 00 00 00         4                 对象键长度
28    4     01 00 00 00         1                 对象键
32    4     0d 00 00 00         13                操作名长度（含结尾 NUL）
36    12    "mochaGetData"      —                 操作名（12 字符）
48    4     00 00 00 03         —                 固定
52    4     00 00 00 00         —                 固定
56    4     命令码               见 §4              **LE**
60    4     子码                 见 §4              **LE**
64    4     数量                 1                 读取元素个数
68    4     地址/轴号             见 §5              **LE**
72    4     00 00 00 00         —                 保留
76    4     期望返回类型          见 §3.3            **LE**
```

### 3.2 响应

```
0..7   47 49 4f 50 01 00 01 01     末字节 01 = Reply
16..19 请求 ID（与请求一致）
28..30 "IDL"                       无数据标志
36..    数据区（按 data[28] 类型标记 / data[32] 尺寸解析）
```

### 3.3 值类型编码

| 请求侧（期望类型） | 响应侧解析 | 长度 | 数据位置 |
|---|---|---|---|
| `0x01` | BYTE | 1 | `[36]` |
| `0x02` | INT16 | 2 | `[36:38]` LE |
| `0x03` | INT32 | 4 | `[36:40]` LE |
| `0x05` | DOUBLE(8，IEEE754) | 8 | `[36:44]` LE |
| `0x06` | DOUBLE(10，扩展) | 16 | `[44:52]`（前 8 字节对） |
| `0x10` | CString | — | 长度 `[36]`，字符从 `[40]` 起 |
| `0xbc` | CString-188 | — | 同上 |
| `0x49 0x44 0x4c`("IDL") | 无返回 | — | — |

## 4. 命令码表（双证据：源码注释 + C# 交付实测）

### 4.1 各数据项的实测请求帧（🟢 本地仿真抓取，2026-09）

现场交付包的 Go 网关自己实现了 M70 协议。把 `/Mitsubishi/CNC/M70/Open/TCP`
指向假机床（端口 683），再逐项 POST，就能拿到每项的真实 GIOP 请求
（复现：`tools/site-probe/gateway_probe.sh`）。**每项一帧、80 字节定长**
（报警那条 84 字节，方法名更长），与 §3.1 的布局完全一致：

```

04 00 00 00 01 00 00 00 | 0d 00 00 00 | "mochaGetData\0" | 00 | <代码> 00 00 00
00 00 00 00 | <参数1> | <参数2>
```

各 `mochaGetData` 项的**代码与参数**（小端 4 字节，偏移 49 起）：

#### 4.1.1 应答侧实测（🟢 2026-09 第二轮，`tools/site-probe/m70_reply_probe.sh`）

手法：**把网关自己的请求回声回去**（`EREP:`），只改必要字节——请求 ID、长度、
对象键全都不用猜；`mock.py` 为此加了 `cut:N`（回声后截断到 N 字节）。

| 试法 | 结果 | 说明 |
|---|---|---|
| 回声 + `[7]=01`（消息类型=Reply） | `error response length` | 长度检查先挂 |
| 回声 + 截断到 **40** 字节 | `error response data` | **长度检查过了**，数据检查挂 → 说明"对"的长度是 40 |
| 回声 + 截断到 36/44/…/84 | 全部 `error response length` | 只有 40 能过长度检查 |
| 改 `[8..11]`（GIOP size）三种值 | `length` / `data` | size 不是这条检查的开关 |
| `GetProgramName`（回声，不截断） | **`'aGetDat'`** | ✅ **CString 取在 `[40]` 起**，与 §3.3 完全一致 |
| `GetStatus`（回声，逐字节改 `[36..48]`） | 恒 `'free'` | 这个字节区间不参与状态判定（或走默认分支） |

## 5. 轴号与坐标类型

**轴号**（C# 交付实测）：`X=1, Y=2, Z=4`（位编码，第 4 轴=8，第 5 轴=16）
> C++ 样例用枚举 `AXIS_X=1,AXIS_Y=2,AXIS_Z=3,AXIS_C=4` —— **两者不一致**，以机床实测为准（建议做成可配置）。

**坐标类型**（命令 `0x25` / `0x03` 的子码）：`1`=工件坐标 · `2`=机械坐标 · `3`=当前位置 · `6`=剩余距离

## 6. 读写流程

### 6.1 读机械坐标（X 轴）

```
request = bytes([
  0x47,0x49,0x4f,0x50, 0x01,0x00,0x01,0x00,
  0x44,0x00,0x00,0x00,            # 长度 68
  0x00,0x00,0x00,0x00,
  id&0xff,(id>>8)&0xff,(id>>16)&0xff,(id>>24)&0xff,   # 请求 ID
  0x01,0xff,0xff,0xff,
  0x04,0x00,0x00,0x00,
  0x01,0x00,0x00,0x00,
  0x0d,0x00,0x00,0x00,
  ord('m'),ord('o'),ord('c'),ord('h'),ord('a'),ord('G'),ord('e'),ord('t'),ord('D'),ord('a'),ord('t'),ord('a'),
  0x00,0x00,0x00,0x03,
  0x00,0x00,0x00,0x00,
  0x25,0x00,0x00,0x00,            # 命令：读坐标
  0x02,0x00,0x00,0x00,            # 子码：机械坐标
  0x01,0x00,0x00,0x00,            # 数量 1
  axis,0x00,0x00,0x00,            # 轴号
  0x00,0x00,0x00,0x00,
  0x10,0x00,0x00,0x00])           # 期望 CString
```

### 6.2 响应解析（C# 交付的 CheckFrame）

```
if len(resp) < 33:                 error(-1) 长度不足
if resp[0:8] != 47 49 4f 50 01 00 01 01:  error(-2) 报文头异常
if int32_le(resp[16:20]) != id:    error(-3) ID 不匹配
if resp[28:31] == "IDL":           无数据
else: 按 resp[28] 类型标记解析（见 §3.3）
```

## 8. 实现坑

1. **长度字段是「总长-12」**，不是总长。写错设备直接不回。
2. **操作名长度 13 但字符串只有 12 字节**（含结尾 NUL），后面 4 字节 `00 00 00 03` 是固定填充 —— 抄样例别自己推。
3. **轴号 1/2/4 是位编码**，不是序号。
4. **`0x03` 命令的多义性**：它是通用"设备数据"命令，语义完全由子码决定（0x02 机械坐标 vs 0x7e 加工参数），实现时必须 `(cmd, sub)` 联合判断。
5. **CString 返回**：长度在 `[36]`，内容从 `[40]` 起 —— 注意偏移 4 字节的空档。
6. **单会话独占**：异常退出后必须重连，旧会话可能残留（机床侧连接数有限）。
7. **写操作风险**：`mochaSetData` 可改参数/变量；`mochaFSRemoveFile` 删程序 —— 生产环境默认禁用。
