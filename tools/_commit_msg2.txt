01 册：程序上下行的两条现场口径 + 传输状态回执在方向 3

* 现场口径（用户给的，FANUC 的规矩）：程序正文**第一行必须是程序号**
  （O0001 / O00001），机床从这一行认程序号。type = 0（NC 程序）先挡一道 ——
  正文没有这一行就回参数错，不发注定被拒的帧；type 1..5 不查这一条。
* start 帧给的是**目录**（//CNC_MEM/USER/PATH1/），不是文件名：给文件路径机床在
  start 那一步就回 EW_ATTRIB=5（官方 SDK 也一样）。program_download 现在自己取
  "目录那一段"，调用方给文件名也行。
* 传输的**状态回执在方向 3**：0x13（end）的应答是 dir 3、体前 4 字节是机床返回码
  （实测 00000005 = EW_ATTRIB）。以前这一族被当成"没有这个数"，把"机床为什么不收"
  整条信息丢了；现在 focas_transfer_exchange() 单独认，翻成
  NCL_FOCAS_ERR_TRANSFER(码)，last_error 出人话。
* 这台模拟器上两个方向都到不了（**官方 SDK 同样**）：下行 start/download4 rc=0、
  end 回 EW_ATTRIB=5；上行的 0x18 dir 4 数据请求机床一声不响（SDK 回 EW_DATA=10）。
  上行仍是"读不到"，但缺的东西更清楚：请求帧已核，差的是应答里程序文本的切法。
* 一条没解决的如实记进 §11.14.4：本 client 的 0x11 与 SDK 逐字节相同，机床却只回
  SDK 那份、对本 client 直接关连接；把 SDK 的原始字节原样重放同样被关 —— 所以不是
  "帧写错了"，机理未明（开口项）。client 侧只保证拿不到应答就报传输错、不假装成功。
* 工具：探针补 --data TEXT；新增 focas_replay.py / focas_replay_verbatim.py
  （裸 socket 重放，用来分辨"帧不对"还是"客户端不对"）。

验证：ctest 43/43；SDK 与 client 两边的帧用 focas_log_summary.py 逐帧对过。
